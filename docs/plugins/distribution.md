# GitHub 仓库、打包与发布

## 标准仓库

每个公开 GitHub 仓库根表示一个插件：

```text
manifest.json  # 必需，UTF-8 对象
main.js        # 必需，最终单文件 JS
ui.json        # 可选，声明式页面
src/           # 作者开发源码，不下载、不安装
tests/         # 作者测试，不下载、不安装
docs/          # 作者文档，不下载、不安装
```

宿主不会执行安装脚本、构建 `src/`、安装 `package.json` 或 Git submodule。请把最终入口提交到仓库根，不能只有源文件。模板在 [`examples/plugins/template`](../../examples/plugins/template)，复制其内容到新仓库根；OBoard 的示例子目录 URL 本身不是可安装仓库地址。

## 地址与不可变来源

接受 `https://github.com/OWNER/REPO`，可带 `.git` 或末尾 `/`。不接受 `/tree/...`、子目录 URL、私有仓库、凭据、query、fragment、自建 GitHub 域名或任意下载地址。ref 独立输入分支、标签或完整 40 位小写提交 ID；省略时先取默认分支。

导入器将 ref 解析为固定 commit，再从其根 tree 获取三个允许文件并核验 Git blob 身份。不拉取整个仓库，不跟随重定向，不继承环境代理。软链接、submodule、缺失必需文件或超限内容失败。Git blob 哈希是完整性关联，**不是作者签名**。

预览显示来源、固定提交、版本、内容 SHA-256 与能力差异。确认必须绑定同一固定提交和预览摘要；分支在两步间移动时不得静默换成新内容。首次安装仍需管理员授权；更新也不自动继承新增权限。不要把固定 commit 宣传为已审核安全。

## ZIP 合同和工具

`oboard-plugin-tool pack <directory> <new-output.zip>` 只读取根入口，忽略开发文件；`check <package.zip>` 校验已有包。路径显式指定，输出不覆盖任何现存文件/链接，文件模式 0600。工具不执行插件、不联网，不输出代码或密钥。

ZIP 最多 1 MiB；清单最多 64 KiB，源码/UI 各 256 KiB。只允许根层两个或三个普通文件，拒绝额外文件、目录、重复名字、路径穿越、符号链接、加密/不支持压缩和不合法编码。工具与安装器调用同一容器解析及运行/UI 校验代码。内容摘要由安装文件内容计算，而非 ZIP 时间戳，因此不要用 ZIP 文件自身哈希替代预览返回的包摘要。

## 发布清单

1. 使用新版本号，确认 `plugin_id` 未变；不同代码不可复用同版本号。
2. 编译、执行模拟 SDK 测试、打包与 check；检查包只有允许入口。
3. 检查所有声明能力、网络来源、UI 动作与文档准确，源码没有凭据。
4. 在测试宿主安装、授权、模拟后进行限定真实测试。记录验证宿主版本与数据兼容性。
5. 经独立发布授权再推送仓库/tag；推荐消费者输入明确标签或 commit。
6. 更新时展示新增权限并重新审核。程序回退不等于私有数据回退，见 [运维](operations.md)。

GitHub 不可达/限流时保留现有安装，稍后重试或上传本地验证包。不要为了安装改为任意 URL、私人 token 或关闭 TLS 校验。
