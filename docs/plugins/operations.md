# 安装运行、更新、卸载和恢复

## 运行环境

默认 Controller 安装不自动安装插件运行时。管理员显式启用插件运行环境，由独立 `oboard-plugin-worker` 服务连接宿主 Unix socket，再启用全局插件开关。Linux 隔离依赖缺失时插件不可执行，不影响代理数据面；不要将 Runner 改为主控 root 进程或关闭隔离。具体服务安装参数以当前 Controller 安装器为准。

上线检查：已安装运行时 → Worker 心跳新鲜 → 隔离可用 → 插件/版本已启用 → grant 精确匹配 → 节点及本地安全策略允许 → 模拟 → 受控真实运行。模拟返回值不等于真实 Agent 状态。

## 更新与回退

1. 预览候选包/固定 GitHub commit，核对身份、版本、内容摘要和权限差异。
2. 新版本静态验证通过后安装，管理员重新审核授权；不要把旧授权提升为新能力。
3. 确认配置符合候选 config_schema，检查私有状态数据版本；不兼容时停用并按作者升级流程操作。
4. 明确切换激活版本。版本切换与既有触发器绑定不是同一个操作，核对触发绑定的 revision，避免旧版本继续调度。
5. 已有 run 保留版本快照，不能在执行中偷换代码；撤销/取消会阻止后续 SDK 调用。

回退选择已保存的不可变版本并重新校验配置、状态和授权。宿主不自动回滚 KV 或已经下发的节点动作，不保证任意旧版本能读取新数据。更新失败时保留原安装，不宣称部分升级成功。

## 故障处理

- 排队：看全局/单插件并发和 Worker 状态，不反复点按钮制造重复动作。
- 超时/取消：先查看 RunAction、Agent task、外部系统实际结果；超时不是证明未执行。
- 权限变化：重新检查版本声明、grant、调用者、目标资源和本地安全策略；不降级走远程 Shell。
- `condition_changed`：资源或 CAS 版本变化，重新读取并预览。
- 网络失败：检查精确 origin、方法、公共 DNS/IP、大小预算；不要输出秘密或响应体做诊断。
- 日志/结果过大：只保留摘要与回执 ID，避免批量原始对象。

默认日志保留 30 天，摘要保留 90 天；不要将运行历史当永久业务存储。

## 停用/卸载/恢复

先停触发并观察在途动作。取消租约不能撤回已送达的签名任务或 HTTP 请求。卸载需明确确认是否保留非秘密数据；无论选项如何，秘密删除、grant 撤销、触发器停用。历史审计仍保留。

备份恢复后插件执行/调度默认关闭，未完成执行不重放，高危授权需重新确认；只通过支持的 Controller 恢复流程重新加密秘密。旧脚本没有业务数据转换或 API 兼容层，不应尝试通过旧脚本接口执行插件。不得手工清空其他业务数据库解决插件问题。
