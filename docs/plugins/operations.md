# 运维

## 运行环境

默认安装与更新不包含插件运行环境。需要时在主控主机上执行面板“查看安装命令”给出的命令（等价于 `OBOARD_ACTION=enable-plugins` 或安装时设置 `OBOARD_INSTALL_PLUGINS=1`）。它安装 `oboard-plugin-worker` 服务与隔离依赖（bubblewrap、uid 映射工具），**不会**开启插件执行。

管理员在插件页开启“插件执行”，并可设置运行策略：暂停全部计划、全局并发（1–8）、单次最长时间（5–120 秒）、日志与执行记录保留天数。

节点侧诊断还需要在该节点上显式允许插件诊断（Agent 本地 `plugins_enabled` 开关，默认关闭，主控无法远程开启）。

## 实例

一个插件可以有多个实例，每个实例独立保存：名称、环境变量与自定义变量、密钥、授权、计划、私有状态（≤128 个键、单值 ≤16 KiB、合计 ≤512 KiB）。实例状态：

| 状态 | 含义 |
|---|---|
| 就绪 | 可运行 |
| 需关注 | 最近连续失败 |
| 待配置 / 配置无效 | 缺少必填项或值已失效（例如所选服务器被删除） |
| 待审核权限 | 新版本扩大了权限 |
| 已自动暂停 | 连续失败 5 次；修复后点击“恢复” |
| 已停用 / 插件已停用 / 未发布 | 由管理员停用或尚无发布版本 |

## 计划与事件

- **固定间隔**：≥1 分钟，按时钟对齐。
- **Cron**：五段式表达式与 IANA 时区。
- **服务器事件**：`server.online` / `server.offline`，只对授权了 `events.server_status` 的服务器触发。

同一实例同时只运行一个执行；错过或重叠的触发合并为一次并记录跳过原因，不补跑积压。手动运行使用幂等键，重复提交不会重复执行。

## 执行记录

每次执行记录触发来源、版本、状态（排队、运行中、成功、失败、超时、已取消、权限不足、超出资源限制）、错误码、能力调用次数、返回值与日志。排队或运行中的执行可以取消：租约立即失效、Runner 被终止，已发出的只读诊断结果会被丢弃。

## 备份与恢复

备份包含插件、实例、配置、加密密钥与状态。恢复时密钥按目标安装重新加密；插件执行保持关闭，所有授权被撤销，未完成的执行被取消，需要管理员逐个复核授权后重新开启。

## 从旧插件运行时升级

升级会清除旧运行时的全部插件数据（代码、授权、密钥、状态、执行记录、Webhook）并关闭插件执行；旧插件需要按新清单重写后重新安装。此迁移登记为 `controller-db-20260930-plugin-capability-runtime`。
