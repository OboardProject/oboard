# 插件开发规范与验证

本文是所有 `oboard-js` 插件的开发与验收入口，适用于读取、诊断、外部 API、通知、定时任务和界面插件。“必须 / 不得”是开发要求，“建议”是设计建议；宿主当前强制执行的范围以清单校验器与网关为准，不能把本文的业务设计要求误认为平台已经自动实现。

字段与方法见 [清单](manifest.md)、[SDK](sdk.md)，隔离与授权见 [安全模型](security.md)，交付见 [打包](packaging.md)，运行与恢复见 [运维](operations.md)。

## 开发流程与契约来源

1. 写明插件目的、触发方式、访问的数据、外部副作用、所需能力和资源范围；先确定是否能完全通过现有 SDK 实现。
2. 从 [`examples/plugins`](../../examples/plugins) 选择最接近的示例，先完成最小清单与一个可验证的 `main(run)`，再增加功能。
3. 定义环境变量、失败行为、单次工作量、重复执行策略及返回结果，再编写业务逻辑与测试。
4. 执行静态检查、实际 Goja 测试和相关网关测试；在授权的 Linux 验证环境完成真实 Runner 验收。
5. 检查最终包、版本、发布者与权限差异。安装验证必须单独记录，不能用源码提交或打包成功代替。

| 契约 | 维护位置 |
|---|---|
| 清单语义与环境值 | [`manifest.go`](../../internal/plugin/manifest.go)、[`environment.go`](../../internal/plugin/environment.go) |
| 编辑器声明 | [`manifest.schema.json`](../../sdk/plugins/manifest.schema.json)、[`oboard.d.ts`](../../sdk/plugins/oboard.d.ts) |
| 能力、资源、速率与预算 | [`capabilities.go`](../../internal/plugin/capabilities.go)、[`limits.go`](../../internal/plugin/limits.go)、[`gateway.go`](../../internal/plugin/gateway.go) |
| JavaScript SDK 与执行 | [`bootstrap.js`](../../internal/pluginruntime/bootstrap.js)、[`runtime.go`](../../internal/pluginruntime/runtime.go) |
| 视图与归档 | [`view.go`](../../internal/plugin/view.go)、[`package.go`](../../internal/pluginpackage/package.go) |

遇到文档、类型声明与宿主行为冲突时，必须核对实现并修正文档或实现；不得靠试探内部 API、放宽授权或添加旧运行时兼容来绕过。示例中的域名与凭据是占位数据，不是可直接使用的服务。

## 运行时与代码组织

- 交付入口固定为 `main.js`，顶层声明 `function main(run)`，可以是 `async`。顶层只定义函数、常量与纯计算；有副作用的 SDK 调用放进 `main` 的明确分支。
- 运行环境是 Goja，不是 Node.js 或浏览器。不得依赖 `require`、`import`、npm 运行时、`process`、`Buffer`、DOM、文件、套接字、定时器、`fetch` 或 WebAssembly。TypeScript 只用于开发时类型检查，交付必须是宿主可编译的 JavaScript。
- SDK 调用同步返回；`async` / `await` 不会让诊断或 HTTP 自动并发。不得用未完成的 Promise、后台回调或忙等待延长任务。
- 每次执行使用一次性 Runner。全局变量不跨运行保存，不能作为锁、去重记录或缓存；需要持久化时使用实例 `state`。
- 输入与输出保持普通 JSON 数据；不得返回循环引用、函数、BigInt 或 SecretRef。数字精度、空值和字符串 ID 要按 SDK 类型处理，不将 ID 当数组下标或名称。
- 将参数构造、签名、结果判定等纯函数与 SDK 调用分离，便于独立测试；不要动态拼接 SDK 方法名来规避静态检查。

## 清单、配置与最小权限

- `manifest.json` 是唯一声明来源。`id` 保持稳定，`runtime` / `entry` 固定；拒绝未知字段和旧格式，不能自行创造能力或别名。
- 每个功能只申请实际使用的能力。读取基础信息、健康、指标、诊断、状态读写各自独立；声明能力不等于已获得授权。
- HTTP 主机优先精确列举，方法只列实际使用项。不能通过任意 URL、自定义变量或通配主机扩大业务用途，更不能访问 Controller 内部 API。
- 配置字段使用准确类型、中文标签、用途说明及合理上下界；不要把布尔、整数、服务器或 JSON 全部降为字符串。关键业务配置应显式声明，不依赖隐藏的自定义变量。
- `depends_on` 只支持字段等值关系；不活动的字段不会进入运行时，代码必须处理缺失。使用默认值时保留合法的 `0`、`false` 和空值语义，不用 `value || fallback` 无差别覆盖。
- 密钥只使用 `secret`，不得硬编码、放入普通默认值或提交到仓库。自定义变量和 `url` 类型都不会绕过权限；即使 URL 字段允许 HTTP，`http.request` 仍只接受 HTTPS。
- 服务器环境值是字符串 ID，选择器的 online 等过滤条件只是配置辅助。执行时仍需处理删除、离线、撤权与 Agent 本地诊断关闭；数字 ID 可被回收，不应据此永久认定历史对象仍是同一台服务器。
- 手动执行成功不证明计划、事件或另一位操作员可用。每次 SDK 调用会重查版本、授权、资源范围、运行策略和发起者权限，必须允许执行中途被拒绝。

## 触发、幂等与外部副作用

- 按 `run.trigger` 分发业务；仅在 `event` 分支使用 `run.event`，界面分支验证 `run.page` 与 `run.action`。未知操作必须拒绝，不能回落到默认写操作。
- 固定间隔最短一分钟，Cron 使用五段式表达式与 IANA 时区。业务周期必须明确时区及跨日规则；`scheduled_at` 是调度时间，不等于实际开始时间或实时签名时间。
- 同一实例同时只有一次执行，重叠触发会合并或跳过、不补跑积压。插件不能假定每个周期或每次状态变化都完整执行；需要连续观察时主动读取当前状态并标明缺口。
- 手动提交的幂等键只约束运行创建，不保证外部 API 恰好执行一次。不同实例也可能操作同一资源。外部写入应优先使用服务端幂等键，并按业务对象和业务周期设计稳定标识，不能仅依赖每次变化的 `run_id`。
- 写操作必须先验证目标与前置条件。读取失败、空结果、响应结构不符或状态未知时不得继续变更资源。不要把页面刷新、普通巡检或错误恢复隐式变成外部写入。
- 取消、超时、异常和本地状态保存失败，不会撤销已经发生的外部请求、通知或状态写入。写请求超时应记录“结果未知”，先查询远端结果再决定是否重试，不能直接报告“未执行”。
- 多步骤任务必须定义部分成功的处理方式，输出每项确认结果和待核实项。不得宣称跨 SDK 调用有事务或自动回滚；危险写操作需要插件自己的明确启用条件，真实资源验证须获得操作授权。

## 预算、失败与重试

当前默认值和硬上限来自 `limits.go`；清单可在上限内调整，宿主全局策略可进一步缩短运行时间。数值限额省略或为 `0` 时使用默认值，不代表无限或禁止调用。

| 单次预算 | 默认 | 宿主上限 |
|---|---:|---:|
| 执行时间 | 30 秒 | 120 秒 |
| Runner 内存 | 64 MiB | 128 MiB（声明最小 16 MiB） |
| SDK 调用 | 200 | 1000 |
| HTTP 请求 | 20 | 100 |
| Agent 操作 | 5 | 20 |
| 日志总字节 | 64 KiB | 256 KiB |

此外，日志最多 1000 行、单行 2 KiB，返回结果最多 64 KiB。HTTP 请求体最多 256 KiB、响应体最多 1 MiB、单请求最长 30 秒，并受剩余执行时间约束。能力还有跨运行的实例级每分钟速率限制，增加单次预算不能取消限流。

- 所有分页、资源遍历和重试都必须有数量上限；按最坏情况计算 SDK、HTTP、诊断和时间消耗，为错误处理与结果保存保留余量。超出单次能力时分批并保存明确进度。
- 依据 `OBoardError.code` 分类，不解析可变错误文案。业务失败使用有意义且不冒充宿主错误的自定义码；不要 `catch` 后返回空对象来伪装成功。
- 权限、配置、参数、目标地址和能力不支持错误直接停止相关操作；`CANCELLED`、`PLUGIN_DISABLED`、运行期限或预算耗尽后不得继续尝试副作用。
- `SERVER_BUSY`、临时网络失败和限流只对可安全重试的操作处理，次数必须有界；没有定时器，禁止忙等待退避。长等待应留到后续调度，持久化下次允许处理时间并检查它。
- 连续失败五次会自动暂停实例。修复后需要管理员恢复；不要吞掉失败以规避暂停。

## 状态、日志与数据最小化

- `state` 按实例隔离，最多 128 个键、单值 16 KiB、合计 512 KiB；键为 1–128 字节可打印文本。它用于小型进度、去重和摘要，不是数据库、日志仓库或密钥存储。
- `state.get` 返回包含 `exists`、`version`、`value` 的对象，不是直接返回业务值。依赖旧值更新时使用 `compareAndSwap`，`expectedVersion=0` 表示键不存在；`STATE_CONFLICT` 时重新读取并重新评估，不能无条件覆盖。
- 明确键名、内容结构和保留策略，清理过期业务记录。读到未知结构应明确报错或走经过测试的数据升级方案，不能静默清空、自动兼容所有旧形状或执行外部补偿。
- 外部操作与状态写入不在同一事务中。成功标记只能在确认结果后写入，同时必须处理“远端成功、本地记录失败”的窗口。
- 日志、返回值、状态、页面快照和通知仅保留必要摘要。不得输出全量 `env`、SecretRef 内部引用、认证头、完整签名 URL、原始响应或用户敏感数据；自动脱敏不能替代开发者的数据最小化。
- 建议记录阶段、资源标识、计数、耗时、非敏感错误码和是否确认成功。不要将 HTTP 成功、通知入队或 Worker 启动描述为最终业务完成。

## 诊断、通知与界面

- `http.request` 从 Controller 网关访问外部 API；`network.*` 在选定 Agent 上探测。两者的网络出口与能力不同，不能用前者冒充节点连通性，也不能用 `httpProbe` 获取业务响应体。
- Agent 诊断要求本地 `plugins_enabled`；离线、忙、平台不支持及目标非公网均需明确处理。Windows 仅支持 TCP、DNS、HTTP 诊断，不能默认具有 ICMP 或 Trace。
- 通知设置业务去重、冷却及恢复条件，避免每次巡检重复报警。管理员渠道、指定用户、套餐用户使用不同能力和授权范围。用户通知的 `queued` 是入队，`unbound` 是无可用渠道，不等于送达。
- 界面只发布 SDK 支持的封闭视图，不提供 HTML、CSS、脚本或任意输入。`pages`、按钮 action 必须在清单中声明，新增页面或 action 需要考虑重新审核。
- 打开页面不启动 Runner；刷新才触发 `ui`，按钮触发 `action`。刷新分支只做读取与展示；外部写操作必须与普通刷新分开，按钮名称明确说明结果，不能假设平台提供额外确认或自由参数。
- `binding` 仅支持指定服务器的基础信息、健康和指标；其他结果写入快照并带采样时间或状态，避免把旧快照伪装为实时数据。快照最多 64 KiB，发布校验失败时旧快照仍在。

## HTTP 参数类型与编码

- headers、query 的每个值必须是字符串或 SecretRef。网关不会自动转换数字、布尔值、数组或对象。
- 数字与布尔参数按目标 API 的规范转为字符串，例如 PageSize: String(1)。数组或对象仅在 API 要求 JSON 字符串时使用 JSON.stringify，不能直接作为 query 值。
- 按 API 规则省略可选参数，不要将缺失值变成字面量 undefined 或 null，也不要因值为 0 或 false 就无条件丢弃。
- query 传未做 URL 编码的字符串，由网关编码。不要预编码值后再交给网关；签名协议要求的编码单独用于构造签名原文。
- json 会序列化为 JSON 请求体，不能与 body 同时指定。接口要求表单时，不能用 json 替代。

~~~js
const query = {
  RegionId: env.REGION_ID,
  InstanceIds: JSON.stringify([env.ECS_INSTANCE_ID]),
  PageSize: String(1),
}
~~~

PageSize: 1 会触发 INVALID_ARGUMENT，错误信息为 “header and query values must be strings or secret references”。HTTP 调用计数增加不代表请求已到达远端：预算可能在参数校验前已经计入。

## HTTP 响应与业务确认

`http.request` 的网络或策略失败抛出 `OBoardError`；收到 HTTP 4xx / 5xx 响应时仍返回响应对象，必须检查 `response.ok` / `status`，不能只靠 `try/catch`。2xx 也不保证业务成功：继续验证 API 自身的错误码、目标标识和结果结构；202 通常只表示已受理。

`response.json` 仅在响应 Content-Type 含 JSON 且解析成功时存在。必须处理空响应、非 JSON、错误页、缺失字段和 `body_base64`，不得无条件读取嵌套属性。限制分页数和结果数量；不要把整个响应直接写进日志或执行结果。

重定向默认关闭，开启时最多三跳且每跳重新校验；携带密钥时强制关闭。不要为追踪重定向扩大到任意主机或将认证信息转发给返回体指定的地址。

## 签名与密钥引用

SecretRef 不是密钥字符串。不能用字符串拼接、模板字符串或 String(ref) 获取或变换密钥；这些操作只能得到引用的展示文字。前后缀使用 withPrefix / withSuffix，HMAC 交给 oboard.crypto，明文只在 Controller 网关内解析。

阿里云 RPC HMAC-SHA1（SignatureVersion=1.0）请求必须满足：

1. 先确定最终参数值，再按参数名排序；签名参数集合不含 Signature。
2. 参数名和值按 RFC 3986 编码；空格为 %20 而非 +；!'()* 必须转义，~ 保留。拼接规范化查询串后，再按协议编码为签名原文。
3. 签名原文中的 HTTP 方法和路径必须与实际请求一致。根路径 POST 的原文为 POST&%2F& 加编码后的规范化查询串。
4. HMAC 密钥必须为 **AccessKeySecret 加末尾 &**，摘要输出必须为 **Base64**。SDK 默认摘要输出为 hex，必须显式指定。
5. 签名后不得改变参与签名的参数、时间戳、nonce、HTTP 方法或路径。

~~~js
function percentEncode(value) {
  return encodeURIComponent(String(value)).replace(/[!'()*]/g, function (ch) {
    return '%' + ch.charCodeAt(0).toString(16).toUpperCase()
  })
}

// query 已包含最终的字符串参数，且尚无 Signature。
const canonical = Object.keys(query).sort()
  .map(key => percentEncode(key) + '=' + percentEncode(query[key])).join('&')
const stringToSign = 'POST&' + percentEncode('/') + '&' + percentEncode(canonical)
query.Signature = oboard.crypto.hmacSha1(
  env.ACCESS_KEY_SECRET.withSuffix('&'),
  stringToSign,
  { output: 'base64' },
)
~~~

时间戳使用当前请求时间，格式遵循目标 API；nonce 每次请求重新生成。run.scheduled_at 适合判断业务周期，不能作为延迟执行时的签名时间。上例仅适用于对应的阿里云 RPC 协议，不能直接套用于其他云 API 或签名版本。

收到 SignatureDoesNotMatch 时，先逐字符比较服务端返回的 string-to-sign 和本地原文。原文一致再检查密钥后缀、摘要算法、输出编码及配置的 AK/SK 是否配对。测试使用虚构凭据；诊断不得输出真实密钥、完整签名请求或含敏感值的签名原文。

## 回归测试要求

测试按插件实际使用的能力选择，未使用的能力不需要堆砌无关用例。每个功能至少有成功、拒绝或失败、边界输入三类证据。

| 验证层 | 必查内容 | 不能证明什么 |
|---|---|---|
| 清单与源码静态检查 | 必填字段、能力声明、环境约束、Goja 可编译、归档白名单 | 不执行 `main`，不证明业务成功 |
| 业务单元测试 | 触发分支、边界值、分页上限、业务判定、幂等与部分失败 | Node 测试不证明 Goja 兼容 |
| 实际 Goja + 测试网关 | 入口、SDK 参数与返回结构、SecretRef、异常、序列化 | 测试替身不证明网络和 Linux 隔离可用 |
| 相关网关或宿主集成 | 权限范围、运行中撤权、预算、超时、状态冲突、脱敏 | 不证明目标部署环境配置正确 |
| 授权环境真实 Runner | Worker → Runner → SDK → 网关 → 完成记录，核对实际版本 | 一次只读成功不证明所有写操作路径 |

按功能补充以下场景：条件字段关闭、必填密钥缺失；事件与页面分支；服务器删除或离线、Agent 策略拒绝；通知无渠道与入队；状态不存在、配额耗尽；重复触发、取消后的外部结果未知；错误快照不覆盖旧数据。权限与密钥相关功能必须有拒绝和脱敏用例。

测试替身必须模拟真实 SDK 的输入约束，不能对任意请求直接返回成功。可参考 [`examples_test.go`](../../cmd/oboard-plugin-tool/examples_test.go) 的 Goja 接入方式，但其中示例成功路径的替身不能替代你自己的失败与协议校验。外部 API 插件至少验证：

- 每种 API 动作都能构造合法请求，覆盖数字、布尔、数组和可选参数；HTTP 测试入口检查 query/header 值类型。
- 从实际发送的参数独立重建服务端签名原文，再用测试密钥验证摘要；不能只调用同一生产签名函数来生成预期值。
- 覆盖密钥后缀、Base64 输出、参数排序、特殊字符、方法/路径与时间戳。SecretRef 测试替身应拒绝被强制转换为明文。
- 将已出现的故障变成回归用例，确认旧实现失败、修复后通过，例如遗漏 & 和数字 PageSize。
- 模拟 API 拒绝、超时及空结果。读取失败时，不得基于缺失数据继续执行外部资源变更。开关机等写操作使用测试替身，不使用真实资源做单元测试。

Node.js 可作为本地测试工具，但插件实际运行于 Goja。Node 测试通过不代表沙箱和网关已经验证；清单检查也只解析、编译源码，不执行插件。发布前还需在实际 OBoard 环境验证使用到的 SDK 路径及返回结构，并记录真实运行是否完成。

### 静态检查的边界

`check` 的未声明能力检查是文本级提示，不是完整数据流分析：别名、动态访问可能漏报，文本也可能误报，纯 crypto 调用另有处理。必须人工逐项对照 SDK 调用与清单，实际安全边界仍由网关执行。

在 OBoard 工作区内，文档或插件示例变更只运行直接相关验证；修改宿主代码时，按受影响范围选择 `internal/plugin`、`internal/pluginruntime`、`internal/pluginhttp`、`internal/pluginpackage`、`internal/pluginsandbox` 或 `cmd/oboard-plugin-tool` 的测试。安全或跨层协议变更需补充相应集成验证，不能仅运行静态检查。

## Runner 维护要求

Worker/Runner 的隔离实现由宿主维护，插件不能自行绕过：

- Bubblewrap 参数必须经目标 Linux 环境验证，不要照搬其他容器工具的参数。--preserve-fds 曾导致 Unknown option，使实际 Runner 无法启动。
- 当前 RPC 使用 stdin/stdout，stderr 用于启动诊断。stdout 不得写普通诊断文本；插件日志通过结构化 RPC 返回。
- 自检和实际运行必须使用相同的 Bubblewrap 参数，还需验证真实子进程的请求、能力调用、回包、日志和完成结果往返。只检查参数字符串或自检启动不足以证明执行链路可用。
- 保留网络命名空间隔离、IPAddressDeny=any、seccomp 和资源限制。外部 HTTPS 经 Controller 网关，节点探测经 Agent；不得为修复启动或签名错误直接给 Worker 开放网络。
- 未知进程退出不能直接归为资源耗尽。保留有界启动诊断，区分运行环境错误、已确认的 OOM、超时和取消。

## 发布前检查

修改已发布插件内容时递增 manifest.json.version；相同版本不同内容会被拒绝。测试代码留在源码仓库，打包只包含 [允许的文件](packaging.md)，不要把测试目录、依赖、缓存或凭据塞入 .obplugin。

提交推送不等于面板已安装新版本。更新后检查执行记录里的插件版本，再运行验证；若连续失败导致实例自动暂停，修复后还需恢复实例。报告结果时区分本地测试通过、已推送、已安装及真实执行成功。


### 发布验收清单

- [ ] 每个声明的触发入口及实际使用的 SDK 路径有验证记录；失败与权限拒绝不会被报告为成功。
- [ ] 声明、源码、类型使用一致；环境说明足以让操作者完成配置，权限保持最小。
- [ ] 副作用、重复执行、结果未知、取消和部分失败有明确处理；日志与返回结果无敏感内容。
- [ ] 单次预算、速率、分页与状态保留有界；没有后台任务、忙等待或依赖 Node / 浏览器对象。
- [ ] 清单版本递增，既有 `id` 和发布者不变；扩大权限、增加必填项、删除或改型字段的影响已说明并验证。
- [ ] 最终 `.obplugin` 已 `inspect`，内容与测试源码一致；不含测试、依赖、缓存或密钥，私钥留在包目录和仓库之外。
- [ ] 权限复核、实例重新配置、状态格式及旧版本回退影响已评估；不能假定切换代码版本会回滚状态或远端副作用。
- [ ] 交付记录区分源码提交、包摘要、安装版本、运行 ID 与真实结果。未完成真实 Runner 验证时明确标记“未验证”，不得写成“全部通过”。

插件新增功能无需自行修改宿主。若确实需要扩展宿主契约，必须同步能力目录、网关校验、授权与资源解析、SDK 实现及类型、Schema、文档和测试；管理操作还需遵守现有 REST/MCP 契约，不能将管理员专属安装、授权或密钥操作开放给插件。涉及迁移时遵守工作区迁移登记与真实旧状态回归要求。
